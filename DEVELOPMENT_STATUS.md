# Development Status

## Broadcast rate-limit fix

The answer failures in the 2026-11-11 real-AI playtests (NPCs failing to answer during broadcast questions) were traced to the web server's own rate limiter, not OpenAI: `/api/npc-response` rejected requests past the configured per-minute cap with the same 429 "Too many requests" shape, and the default cap was 10/minute — less than one nine-NPC broadcast plus a follow-up. The default `OPENAI_MAX_REQUESTS_PER_MINUTE` is now 30, which fits broadcasts and normal paced play while keeping the cost guard; the limiter itself is unchanged. New `tests/rateLimitBroadcast.test.mjs` adds 2 cases; full regression passes and `npm run sample` PASS.
## Mention-matching fix (romaji names)

Fixed the defect behind the 2026-11-11 playtest slip in which an NPC asked about Hana (romaji "hanaと対決するか？") answered about the dead Aoi: `extractMentionedPlayerIds` substring-matched Aoi's one-letter alias "A" inside "hana" and returned roster order, so the first "mentioned" player was Aoi. One-letter labels now count only when they stand alone (non-letter boundaries), and matches are ordered by longest matching label. New `tests/mentionMatching.test.mjs` adds 6 cases; full regression 839/839 and `npm run sample` PASS.

## Log export (Save Log) slice

A Save Log button (D-017) downloads a text export of the current game: player log and votes from the public snapshot, plus the developer snapshot and full developer event log when Developer Mode is on. The pure builder lives in `public/logExport.mjs`; sessions remain unpersisted (D-009). New `tests/logExport.test.mjs` adds 3 cases; full regression 833/833 and `npm run sample` PASS.

## Broadcast question （全員に話しかける) slice

Broadcast questions (D-016) are implemented. The new `ask_all` player action asks one question to every living NPC in roster order through the ordinary per-NPC response path: the question is logged once (addressed to 全員）, question pressure is applied exactly once, and ask-based claims can fire for any NPC under the existing conditions. The browser gained an "Ask All" button next to Ask, and the CLI an `ask-all` command. New `tests/askAll.test.mjs` adds 6 cases; full regression 830/830 and `npm run sample` PASS. Awaiting the user's real-AI playtest.

## Rescue claim （土壇場CO) slice

Rescue claims (D-015) are implemented. Inside the now-asynchronous `runVote()`, a living, not-yet-claimed seer, medium, or knight who would be executed by the provisional tally claims first — engine-fabricated from their own private knowledge, including a bare declaration when they have no results yet — and the vote is re-cast with the claim's suspicion effects applied. Registered public claims now shift other NPCs' suspicion on every registration path: uncontested claims are believed by default (claimant −3, seer results ±4), contested seer claims raise suspicion of both claimants (+2) with weaker results (±2). A rescue seer claim with results runs the existing D-014 madman counter-claim decision before the re-vote, so a rescue claim is not automatically believed. Only final votes are recorded. Werewolves and the madman do not rescue-claim. Awaiting the user's real-AI playtest.

## Role-leak wording unification

The deterministic denial and deflection wordings in `buildNpcResponseRequest` no longer depend on the hidden role: the werewolf-only phrasings found in the 2026-11-09 playtest are gone, and every role uses the same text. Regression coverage in `tests/deflectionWording.test.mjs`. This covers the fixed template (pseudo) wording; the real-AI composition path can only be checked by playtest.

## Phase 6 madman counter-CO decision slice

The D-014 controlled `chooseAction` trial is implemented for the nine-player madman countering proactive seer claims. The engine owns candidate validation, safe-silence fallback, fabricated results, claim registration, and privacy boundaries. `runNight()` now awaits the day-start decision; the existing browser, CLI, and sample dispatch paths already await commands. Default and sample five-player behavior remains unchanged.
